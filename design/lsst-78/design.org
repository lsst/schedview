* Scope

Add the first simulated visit's RA, declination, altitude, and azimuth to
the =description= of =lsstcam_prenight= RSS items generated by
=schedview.reports.make_report_rss_feed=. Preserve existing statistics.
Do not change nightsum descriptions, other report types, the RSS channel
description, or the report link table. Implementation status is tracked
in the plan below.

* Existing Flow

=make_report_rss_feed= summarizes caller-supplied =prenight_visits= with
=schedview.compute.smallsum.compute_tinysum=, using =t_eff=,
=visitExposureTime=, and =all_science=True=. The resulting DataFrame is
indexed by =dayObs=. The prenight branch formats matching rows through
=_format_summary_desc= and =RSS_PRENIGHT_DESC_FORMAT=; nightsum uses a
different template. Simulation selection and retrieval remain the
caller's responsibility.

* Summary Data

Add an optional =include_first_visit_coordinates=False= parameter to
=compute_tinysum=. Enable it only in the prenight call from
=make_report_rss_feed=, independently of =all_science=.

When enabled, append four numeric columns, in degrees:

| Output column            | Simulation input column |
|--------------------------+-------------------------|
| first_visit_ra           | fieldRA                 |
| first_visit_decl         | fieldDec                |
| first_visit_alt          | altitude                |
| first_visit_az           | azimuth                 |

For each =dayObs=, select the row with the earliest finite
=observationStartMJD= among the supplied visits. Break equal-time ties
by original input row order. All four values must come from that same
row; do not aggregate each coordinate with =groupby.first()=, which can
skip nulls independently and mix visits. Do not assume input is sorted,
use the DataFrame index as a visit identifier, or mutate the input.

Copy coordinates without conversion from the simulation's degree-valued
columns. Altitude and azimuth are those recorded for the selected visit,
not coordinates recomputed for the briefing's generation time.

If the start-time column is absent or a night has no finite start time,
return missing values for all four coordinates. An absent coordinate
column or non-finite coordinate produces a missing value for that field;
do not substitute a later visit. This preserves support for existing
minimal visit DataFrames. With the option disabled, the existing summary
schema and input requirements remain unchanged.

Accept numeric strings and select visits using their numeric start times.
Treat unparseable start times as missing. Exclude boolean and datetime
start times before numeric conversion. These rows are absent from
first-visit selection only; they still contribute to existing statistics.
On the selected row, an unparseable coordinate becomes missing for that
field without substituting a later visit.

Issue an informative Python =UserWarning= once per category per call:
unsupported boolean/datetime start times, unparseable start times, and
unparseable selected coordinates. Coordinate warnings identify the
affected columns. Missing and non-finite values do not warn; neither do
invalid coordinates on visits that were not selected. Disabled mode does
not validate these optional columns or emit these warnings.

* RSS Presentation

Extend =RSS_PRENIGHT_DESC_FORMAT= with an optional =first_visit= fragment.
=_format_summary_desc= builds this fragment for prenight only, rounding
finite coordinates to two decimal places and labeling their units:

Place the coordinate fragment on its own line. Its position relative to
the other description lines is unrestricted.

#+begin_example
First simulated visit: RA=123.45 deg, decl=-45.67 deg, alt=60.12 deg, az=210.34 deg;
#+end_example

Use =decl= rather than =dec= to avoid ambiguity with "decimal".
Wrap displayed RA and azimuth into [0, 360) before and after rounding,
so values rounding to 360 degrees display as =0.00 deg=. Leave the
stored summary coordinates unchanged.
Render a missing field as =unavailable=. Omit the entire line when all
four fields are missing. Keep existing blank descriptions when no
simulation visits match the report night. Leave =RSS_DESC_FORMAT= and
all nightsum text unchanged. The existing description-based GUID hash
will naturally reflect changes in the displayed coordinates.
