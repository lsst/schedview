* Scope

Add the first simulated visit's RA, declination, altitude, azimuth, and
band to the =description= of =lsstcam_prenight= RSS items generated by
=schedview.reports.make_report_rss_feed=. Preserve existing statistics.
Do not change nightsum descriptions, other report types, the RSS channel
description, or the report link table. Implementation status is tracked
in the plan below.

This design was revised on 2026-11-02 in response to =review1.org=.
The feature extracts fields from scheduler output; it is not a general
DataFrame validation facility. Keep the implementation and tests
proportionate to the package's limited target QC level. On 2026-11-03,
the design was extended to include the selected visit's band.

* Existing Flow

=make_report_rss_feed= summarizes caller-supplied =prenight_visits= with
=schedview.compute.smallsum.compute_tinysum=, using =t_eff=,
=visitExposureTime=, and =all_science=True=. The resulting DataFrame is
indexed by =dayObs=. The prenight branch formats matching rows through
=_format_summary_desc= and =RSS_PRENIGHT_DESC_FORMAT=; nightsum uses a
different template. Simulation selection and retrieval remain the
caller's responsibility.

* Summary Data

Add an optional =include_first_visit_coordinates=False= parameter to
=compute_tinysum=. Enable it only in the prenight call from
=make_report_rss_feed=, independently of =all_science=.

When enabled, append four numeric coordinate columns, in degrees, and
one band column:

| Output column            | Simulation input column |
|--------------------------+-------------------------|
| first_visit_ra           | fieldRA                 |
| first_visit_decl         | fieldDec                |
| first_visit_alt          | altitude                |
| first_visit_az           | azimuth                 |
| first_visit_band         | band                    |

For each =dayObs=, select the row with the earliest finite
=observationStartMJD= among the supplied visits. Break equal-time ties
by original input row order. All five values must come from that same
row; do not aggregate each field with =groupby.first()=, which can
skip nulls independently and mix visits. Do not assume input is sorted,
use the DataFrame index as a visit identifier, or mutate the input.

Copy coordinates without conversion from the simulation's degree-valued
columns. Altitude and azimuth are those recorded for the selected visit,
not coordinates recomputed for the briefing's generation time.
Copy band directly from the selected row's =band= column without
conversion; it is a band label, not a numeric coordinate. Prenight
simulation visits always contain coordinates and a band. Do not add
tests for simulated visits missing either.

If the start-time column is absent or a night has no finite start time,
return missing values for all five fields. An absent coordinate
column produces a missing value for that field; do not substitute a
later visit. Missing or non-finite coordinates are displayed as
=unavailable=. They need not be normalized in the summary. This preserves
support for existing minimal visit DataFrames. With the option disabled,
the existing summary schema and input requirements remain unchanged.
If no first visit can be selected, its summary band is also unavailable.

When supplied, start times and coordinates must be numeric, as in
scheduler output. Do not add numeric-string coercion, per-value type
inspection, malformed-input recovery, or feature-specific warnings.
Invalid input types may raise ordinary pandas or NumPy errors; their
behavior is outside this feature's contract. Filtering non-finite start
times affects first-visit selection only, not existing statistics.

* RSS Presentation

Extend =RSS_PRENIGHT_DESC_FORMAT= with an optional =first_visit= fragment.
=_format_summary_desc= builds this fragment for prenight only, rounding
finite coordinates to two decimal places and labeling their units:

Place the first-visit fragment on its own line. Its position relative to
the other description lines is unrestricted.

#+begin_example
First simulated visit: RA=123.45 deg, decl=-45.67 deg, alt=60.12 deg, az=210.34 deg, band=r;
#+end_example

Use =decl= rather than =dec= to avoid ambiguity with "decimal".
Wrap displayed RA and azimuth into [0, 360) before and after rounding,
so values rounding to 360 degrees display as =0.00 deg=. Leave the
stored summary coordinates unchanged.
Render a missing or non-finite coordinate as =unavailable=. Display band
as its label, without degree units or numeric formatting; render an
absent or null band as =unavailable=. Omit the entire line only when all
five fields are unavailable. Keep existing blank
descriptions when no simulation visits match the report night. Leave
=RSS_DESC_FORMAT= and all nightsum text unchanged. The existing
description-based GUID hash will naturally reflect changes in the
displayed coordinates or band.
